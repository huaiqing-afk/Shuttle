# LESSONS — 踩坑账本

只记真实回归、被驳回或测试失败的事故；技术验证的未通过项记入 work/verification.md，不冒充历史教训。最多 20 条，超限前提炼检查后归档。

## L01 · 终端写路由只认字面量 "validation"，真实 ID 全部被拒（2026-10-24）

- **事故现场**：app.go 的 WriteTerminal/ResizeTerminal/CloseTerminal 条件写成 `id != "validation" || a.session == nil` 才放行，而 launch() 生成的真实终端 ID 是 "t1/t2…"。已打包的验证版 exe 里，输入、尺寸、关闭三条路由对真实终端一律返回 "terminal not found"，终端实际只能看不能敲。
- **排查症状**：全部门禁绿——测试没覆盖"以 launch 返回的真实 ID 调写路由"的用例；人工验证只逐项确认了启动与输出，输入验收当时未执行。
- **根本原因**：为隔离测试留的固定 ID 与生产 ID 生成逻辑脱节；路由判定是"字符串等于哨兵值"而不是"查表命中"。T08e 多终端改造重写为 `a.sessions[id]` 查表后顺带根除。
- **硬规则**：桥接方法按 ID 查表路由，禁止与字面量哨兵值比较；改动写路由时必须有用例证明"launch 返回的 ID 能写入"。

## L02 · Wails Windows QuestionDialog 忽略自定义按钮，退出确认永远不通过（2026-10-24）

- **事故现场**：beforeClose 弹 QuestionDialog 并传 Buttons ["退出","取消"]，判断 `answer != "退出"` 则阻止关闭。Wails 在 Windows 上忽略 Buttons 数组，固定返回 "Yes"/"No"——用户点"是"想退出，answer 是 "Yes"，永远 ≠ "退出"，窗口关不掉，进程残留。
- **排查症状**：门禁全绿（Go 测试无法覆盖 GUI 对话框返回值）；旧版单终端同样有此雷，但人工验收从未在"终端运行中"场景点过窗口 ✕，多标签版终端常驻后才暴露。
- **根本原因**：假设了 Wails MessageDialog 的跨平台返回值一致性，没查证 Windows 实现；确认路径从未被真实点击过。
- **硬规则**：对 GUI 框架的原生对话框，按实测返回值建映射（Windows: Yes/No/Cancel），确认集合与取消集合都要显式枚举；弹窗调用失败必须 fail-open（放行关闭），禁止让"确认失败"变成"永久锁死"。
- **第二层（同日复测暴露）**：确认已放行后仍"只关终端、不关窗口"。根因是 OnShutdown 里逐个 `s.Close()`，而 Close 等 ConPTY 读协程排空（readDone），排空依赖 `EventsEmit` 把输出送进此时已退出的消息循环——退出被无限期阻塞。修复：shutdown 并行关闭 + 2 秒上限放行。
- **硬规则补充**：退出路径上的清理必须"有界"——任何等待（网络、进程、协程排空）都要带超时；关终端要保证子进程先死（pty.Close），收尾等待允许超时放弃。

## L03 · 全局快捷键用普通 Ctrl+字母，被聚焦终端当成 ^T 吃掉（2026-10-24）

- **事故现场**：设计快捷键 Ctrl+T 开新终端、Ctrl+1..8 切换。自动化测试聚焦终端后按 Ctrl+T，pwsh 收到 ^T 控制字符（截图可见 `'TGet-Location` 命令未找到），新标签没开。
- **排查症状**：前端 keydown 监听存在，直接在页面上按有效；唯独终端聚焦后失效。
- **根本原因**：终端是全焦点接收组件，普通 Ctrl+字母属于终端自身语义（xterm onData 透传给 ConPTY）。全局快捷键与终端输入面重叠时，终端优先。
- **硬规则**：本应用全局快捷键只允许 Ctrl+Shift+字母 与 Ctrl+Tab（切换），普通 Ctrl+字母永远归终端；Alt+数字类组合禁用（与常见截图/启动器全局热键冲突，实测触发用户截图工具）。

## L04 · 关闭终端偶发卡死：ClosePseudoConsole 只请求退出，子进程不配合就无限等（2026-10-25）

- **事故现场**：`TestConPTYCloseActiveProcess` 约每 60 次偶发失败（`close did not complete`，10 秒超时），临时目录还被占用；堆栈显示 `Close` 卡在 `os.(*Process).Wait` 的 `WaitForSingleObject(INFINITE)`。
- **排查症状**：单独跑多数通过，压力循环 60 次必现一次；goroutine 转储显示 `waited`、`readDone` 都已关闭，只剩进程等待。
- **根本原因**：`ClosePseudoConsole` 只是向客户端发送关闭事件，不保证进程退出；pwsh 正在执行 `Start-Sleep` 时不处理该事件，`proc.Wait()` 无超时故永久等待。与 L02 同属"清理等待必须有序"规则。
- **硬规则**：关闭终端必须自己持有进程句柄（`OpenProcess`），先请求退出，限时等待（当前 1.5s），超时用 `TerminateProcess` 终止并再次有界等待；禁止对子进程使用无超时的 `Wait`。回归测试 `TestCloseIsBoundedAndTerminatesChild` 断言关闭在 8 秒内返回且子进程消失。

## L06 · 预览假数据掩盖 Go 桥接结构差异（2026-10-25）

- **事故现场**：安装几何测试传入嵌套 `Step.Item` 假数据，Go 的匿名嵌入默认却平铺字段；Wails 生成器还对 `Package` 保留字发出警告，测试能绿而真实预览存在结构错配。
- **排查症状**：门禁通过，但生成的 Step 模型没有前端读取的 Item/Command 字段。
- **根本原因**：几何假数据未经真实序列化契约校验；把核心嵌入结构直接暴露给生成器。
- **硬规则**：桥接返回显式 DTO；核心序列化测试断言 Item 嵌套且 Args 不泄露；真实 exe 必须生成一次预览并断言包名出现，禁止以假数据几何通过替代桥接联调。

模板：事故现场 → 排查症状 → 根本原因 → 可机器验证的硬规则。

## L05 · 几何验收只量容器，8px 间距漏网（2026-10-25）

- **事故现场**：T10f 首轮几何检查 9 组全 PASS，`shellGap=0`、`minSiblingGap=null`。但快捷键行的三个输入框用 `gap-2`（8px），违反 AGENTS.md 的 12px 安全线——测试没报，因为只量了 header/aside/main 这类容器，容器之间本就相切（边框相接），而面板内控件纵向排列、没有"同一行成对控件"可测。
- **排查症状**：`panelGap=null` 是空值而非失败值；把容器纳入重叠判定后，`header` 与其子元素被判为"重叠"（包含关系），说明判定维度本身错了。
- **根本原因**：把"无横向滚动 + 容器不重叠"当成了几何验收的全部，没有遍历对话框内每个 flex 容器的相邻兄弟；空测量值被当作通过。
- **硬规则**：几何验收必须（1）遍历目标区域内每个 `display:flex` 容器的相邻子元素，按同行/同列取间距最小值并断言 ≥12px；（2）重叠判定排除祖先-后代包含关系；（3）测量值为空（null）视为失败，不得视为通过。
- **第二层（同日实机复测）**：无头测试 13 组全绿，真实 exe 却装不进 1080×720 屏幕——`main.go` 的 `MinWidth/MinHeight` 是 960×600 DIP，而该屏幕在 125% 缩放只有 864×576 DIP、150% 只有 720×480 DIP，窗口被强制撑到屏幕外。
- **硬规则补充**：窗口最小尺寸必须按"目标最小分辨率 × 目标最大缩放比例"反算，写成 DIP 常量并注释来源；几何验收必须先断言窗口能装进该屏幕可用区域，再谈内部无重叠——装不下的窗口，内部测得再干净也没有意义。
